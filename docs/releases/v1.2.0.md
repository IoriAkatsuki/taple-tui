# taple-tui 1.2

本地 Cookie 导入、真正无头的独立 Chromium 运行时与原生 macOS Metal。

## 更新

- 新增 `--import-cookies FILE`：支持 Netscape Cookie Jar 和浏览器 JSON 数组，仅导入程序专用 profile；严格校验域、作用域、有效期、文件权限和大小，不读取个人浏览器数据库、不记录 Cookie 值。
- 保留 Cookie 的会话、HttpOnly、Secure、SameSite 和 host-only 语义。已授权会话拒绝混入；输入文件不改写。导入后继续运行 TUI，不自动播放。
- 修复从头重播当前集合时同一首曲被误报为加载失败的问题。
- 修复状态回读等待会话锁时忽略 250ms deadline、延迟后续控制的问题。
- macOS 使用系统 Metal；生成的 shader 使用精确归一化，修复 Intel 原生 runner 上的颜色偏差，不放宽 CPU/GPU 一致性阈值。
- Linux CI 明确选择具有可用 sandbox 的已安装浏览器，不再误选受到 Ubuntu AppArmor 限制的解包 Chromium；不禁用 sandbox。
- 修复默认 `make package` 的版本号传播，保留可复查的原生失败诊断。

## 使用

```sh
chmod 600 "$HOME/apple-music-cookies.json"
./taple-tui --import-cookies "$HOME/apple-music-cookies.json"
```

Windows 的文件 ACL、允许格式和会话边界见 [Cookie 导入说明](https://github.com/IoriAkatsuki/taple-tui/blob/v1.2.0/docs/cookie-import.md)。文件应放在仓库之外，勿发到聊天或 issue。

## 运行边界

发布包不捆绑 Chromium、FFmpeg 或 Widevine。可使用 `TAPEFOX_BROWSER` 指定独立 Chromium 系运行时，或将完整运行时放在程序旁的 `runtime/chromium/`。正常后台使用 `--headless=new`，不要求已有系统 Chrome；首次官方交互登录仍需图形会话。

Cookie 写入、网页授权、订阅有效、DRM 许可证和实际出声是独立条件。导入不保证恢复登录，不绕过 Apple 授权；系统 FFmpeg 不能替代 CDM。无账号 smoke 和 GPU/构建测试不能替代真实订阅账号的完整歌曲验证。

Windows/macOS 包未签名或公证，不需要也不建议关闭系统安全保护。各包附带 SHA-256 校验值，只有全部原生构建通过后才发布。
